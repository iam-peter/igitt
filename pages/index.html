igitt

A git tool combining what gitk and git gui do, each in a mode of its own, which also folds changes into the commits not pushed yet and edits the history without touching the working tree.

Download Nightly Source on GitHub

What it does

  • Explore, commit and rework in three modes: History, Changes and Compose.
  • Browse the history of every branch as a graph and search it, its messages or its code.
  • Step through every revision of a file below the history, each line blamed and its commit picked in the graph, and see its whole history flow from revision to revision.
  • Stage and commit single lines, hunks, files or several files at once; discard them, stash them away, all or only what is staged, or ignore them.
  • Fetch, pull, merge and rebase, each the way you choose; continue or abort what stops at conflicts.
  • Answer what git and ssh ask, a password, a passphrase or a new host, in a dialog.
  • Get back what a deleted branch, a dropped stash or a reset too far left behind.
  • Make, switch, rename and delete branches, push them anywhere and delete them on a remote; make, push and delete tags.
  • Cherry-pick one commit or several, revert and reset, move commits onto another base, check out any commit, compare any two, and bisect for the one that broke something.
  • See who signed a commit and whether the signature checks.
  • Open a change in your own diff or merge tool.
  • Clone or start a repository, shallow or without the file contents for a big one, or reopen a recent one; keep its remotes, worktrees, submodules and a sparse checkout; save and apply patches; lock files in Git LFS.
  • Drag changes onto a commit not pushed yet to fold them in, with a suggestion where they belong.
  • Reword, move, squash and drop commits like git rebase -i, without touching the working tree.
  • Compose several commits at once: drag changes, or single lines of them, into groups, fold them into commits not merged yet, or take them out again.
  • Resolve conflicts with ours and theirs side by side, picking each conflict's lines.
  • Push for review to Gerrit and see the state of GitHub pull requests and GitLab merge requests.
  • Pick a theme: Light, Dark, Dracula, Alucard, the four Catppuccin flavors, or one of your own.

Three modes

History explores, as gitk does: the commit graph above, the project's files and the diff of what you pick below. Changes commits, as git gui does: the changed files and the commit form beside their diff, under a strip of the commits not pushed yet. Drop selected lines or a whole file on one of those commits to fold them in; igitt tags the commit they most likely belong in. Compose reworks those commits together with the changes. Switch with the tool bar or Ctrl+1, 2 and 3. More in the README.

Composing commits

The Compose mode puts commits together by what they are about rather than by file. Every changed line is a card; drag cards into groups, one per commit, each with its own message, and split a hunk by dragging over its lines. Scrolled to the left are the commits of the branch not pushed yet: drop a change onto one to fold it in, drag one of its changes back out into a group or onto another commit, or reword, move, squash and drop it from its menu. A timeline above shows where you are. More in the README.

A file's history

Switch on Flow in the time-lapse view to see a file's whole history at once, as a Sankey diagram. Each commit that touched the file is a node, a bar as long as the file was then, line 1 at the top. Between two nodes the lines flow from their old place to their new one: kept lines in gray, edited ones in orange, removed ones narrowing in red to where they went and fading out, added ones fading in and widening in green from where they came. Above each node its counts, below it its commit. Click a node to show that revision underneath, with what it added, edited and removed in the same colors; the wheel scrolls through the history and Ctrl+wheel zooms. More in the README.

Beside the scroll bar, a strip shows the whole file at once with the changes of the revision on display: green where it added lines, orange where it edited them, red where it removed them, and a frame around the lines in sight. Click or drag it to jump there. On the flow, the current node marks the same lines, and dragging along it scrolls the code too.

Searching and getting work back

The search takes code: to find the commits that added or removed a text, as git log -S does, or with regular expressions those that changed a line matching it. It combines with author:, message: and the other terms, and runs beside the rest, so the window never waits for it. More in the README.

Recover Lost Work, in the repository menu, lists where HEAD was and the commits nothing refers to any more: the tip of a branch deleted, a stash dropped, what a reset left behind. Each shows in History, becomes a branch again, or the place the branch is reset to; a dropped stash goes back among the stashes. More in the README.

When a remote wants a user name, a password or a key's passphrase, or ssh asks whether to trust a new host, igitt asks in a dialog: it is git's and ssh's askpass program. A credential helper or an agent remembers the answers.

igitt remembers the repositories it opened. Started outside one, it shows them on a start page, beside Open, Clone and New Repository; Open Recent in the repository menu has them too.

Signatures, more at once, bigger repositories

A signed commit has a shield before its subject: green when the signature checks, red when it is bad or the key is revoked, gray when this computer cannot tell; the tooltip names the signer. Only the rows on screen are checked, so gpg never runs through the whole history. More in the README.

Ctrl+click and Shift+click pick several files in a change list, and their menu stages, discards or stashes them together. In History, Ctrl+click marks several commits to cherry-pick at once, oldest first; and Move onto This moves a branch's later commits onto another base, as git rebase --onto does.

The commit form starts from commit.template; an amend can be made yours, dated now; and the arrow next to Commit commits once without the hooks.

A big repository clones with only its last commits, or without the file contents until they are needed, deepens later, and keeps only the folders you list checked out. igitt fetches in the background too, asking for nothing.

Themes

igitt draws its controls in a style of its own and takes every color from a theme, the graph, the diffs and the syntax included. A theme of your own is a small JSON file that names a palette and the roles it changes; igitt reads it again as soon as you save it. How to write one.

Debian and Ubuntu

The APT repository brings igitt with its own Qt and installs git with it. It needs git 2.40, so Ubuntu 24.04 or Debian 13 and newer.

sudo curl -fsSLo /usr/share/keyrings/igitt-archive-keyring.asc https://iam-peter.github.io/igitt/key.asc
echo "deb [signed-by=/usr/share/keyrings/igitt-archive-keyring.asc] https://iam-peter.github.io/igitt/apt stable main" | sudo tee /etc/apt/sources.list.d/igitt.list
sudo apt update && sudo apt install igitt

The repository is signed with the key E61A 05C6 0E8A D423 C403 6586 D3D1 B02A 57B5 9B54.

Other systems

Each release has an AppImage for any Linux, a zip for Windows and a disk image for macOS. igitt runs the git command line, so git 2.40 or newer has to be installed. The macOS app isn't signed: open it with a right click and Open the first time.
